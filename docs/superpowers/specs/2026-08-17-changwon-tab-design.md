# 창원시 전용 탭 — 설계

## 배경

사용자가 경상남도 창원시에서 나오는 입찰 공고에는 모두 참여할 예정이다. 지금은 "입찰정보" 탭에서 검색창에 "창원"을 입력하거나 지역 필터로 좁혀야 하는데, 매번 그렇게 찾기보다 항상 바로 볼 수 있는 전용 탭이 있으면 좋겠다는 요청이다.

## 목표

1. 상단 탭 바에 "창원시" 전용 탭을 추가한다.
2. 창원 관련 공고 전체(상태·참가여부 무관)의 참가 진행률을 한눈에 보여준다.
3. 기존 입찰정보 탭의 검색·필터·참가상태 편집 기능을 그대로 쓸 수 있게 한다.

## 창원 판별

`classifyChangwon(bid: BidItem): boolean` — `bid.공고명.includes('창원') || bid.공고기관.includes('창원')`. bid-monitor 쪽에서 이미 같은 방식(공고명/공고기관에 '창원' 포함)으로 걸러서 정상 동작을 확인했다. Notion 데이터에 새 필드를 추가하지 않고 클라이언트에서 즉시 계산하는 파생값이며, 기존 `classifyAgency`와 같은 패턴이다.

## UI

### 탭 바

`레퍼런스 / 공모전 / 입찰정보 / 창원시 / 링크` — "창원시" 탭을 "입찰정보" 다음에 추가한다. 클릭 시 로직은 "입찰정보" 탭과 동일하게 `bidsLoaded`가 false일 때만 `/api/bids` + `getBidParticipations()`를 호출한다 (두 탭이 같은 `bids`/`participations` 페이지 state를 공유하므로 어느 탭을 먼저 열든 한 번만 로드됨).

### 진행률 요약 (`ChangwonView` 상단)

창원 판별을 통과한 전체 공고(상태·참가여부 필터와 무관하게 전부) 기준으로 한 줄 요약:

```
전체 N건 · 참가완료 M건 (낙찰 X · 패찰 Y · 결과대기 Z)
```

`M`은 `participations[bid.공고번호]?.status === '참가완료'`인 건수, `X`/`Y`/`Z`는 이미 있는 `deriveOutcome(bid, participation)`의 반환값(낙찰/패찰/결과대기)을 각 건에 적용해서 센다. 상태 필터(공고중/낙찰/유찰) 선택과 무관하게 항상 창원 전체 기준으로 고정 표시한다 — 필터를 만지면 아래 목록은 좁아져도 이 요약 숫자는 그대로 "전체 그림"을 보여줘야 한다.

### 목록

요약 아래에는 기존 `BidsView` 컴포넌트를 그대로 재사용한다. 다른 점은 `bids` prop으로 `classifyChangwon`을 통과한 공고만 필터링해서 넘기는 것뿐이다. 검색창·지역 드롭다운·발주처유형 필터·참가여부 필터·상태 필터(공고중/낙찰/유찰 pill)·참가상태 인라인 편집은 전부 기존 그대로 작동한다.

`ChangwonView`는 자기 자신만의 필터 state(검색어/지역/발주처유형/참가여부/상태)를 갖는다 — "입찰정보" 탭과 별도로 유지해서 두 탭을 오갈 때 필터가 서로 섞이지 않게 한다. state가 페이지 언마운트 없이 유지돼야 하므로(BidsView와 마찬가지로 탭 전환 시 컴포넌트가 언마운트됨) 이 필터 state들도 페이지 컴포넌트(`Home`) 레벨에 둔다.

## 범위 밖

- 지역 드롭다운을 창원 탭에서 숨기거나 단순화하지 않는다 — 어차피 창원 건은 전부 "경남"으로만 찍혀 있어서 드롭다운이 사실상 무의미하지만, `BidsView`를 그대로 재사용하는 게 목표라 손대지 않는다.
- Supabase나 Notion에 "창원 여부"를 저장하지 않는다 — 매번 클라이언트에서 즉시 계산.
- 진행률 요약 이외의 별도 통계(구간별 낙찰률 등)는 추가하지 않는다.

## 테스트 / 검증 방침

자동화 테스트 없음. 검증은:
1. `npx tsc --noEmit` / `npm run build`
2. 브라우저에서: 창원시 탭 클릭 → 진행률 요약 숫자가 실제 창원 건수·참가완료 건수와 일치하는지 확인, 검색/필터가 기존 입찰정보 탭과 동일하게 동작하는지 확인, 입찰정보 탭에서 설정한 필터가 창원시 탭으로 안 넘어오는지(독립 state) 확인.
