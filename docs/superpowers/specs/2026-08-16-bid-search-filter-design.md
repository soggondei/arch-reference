# 입찰정보 검색·필터 — 설계

## 배경

`app/page.tsx`의 `BidsView`(입찰정보 탭)는 현재 상태(공고중/낙찰/유찰)와 참가여부(전체/참가필요/참가완료/패스) 두 가지 필터만 제공한다. 공고 건수가 늘어나면서 발주처 유형(교육청/지자체/조달청 등)이나 지역, 공고명·기관명 텍스트로 좁혀볼 수단이 없어 원하는 공고를 찾기가 번거롭다.

## 목표

1. 공고명·공고기관 텍스트 검색을 추가한다.
2. 발주처 유형(교육청/지자체/조달청/농어촌·수산/국방·군부대/대학교/공사·공단·진흥원/기타)으로 필터링한다.
3. 지역(시·도)으로 필터링한다.

## 발주처 유형 분류

`공고기관` 문자열을 우선순위 순서로 키워드 매칭해 8종 중 하나로 분류하는 순수 함수 `classifyAgency(공고기관: string): AgencyType`을 추가한다. 첫 번째로 매칭되는 규칙이 적용된다 (순서 중요 — 예: "OO교육청"은 지자체 패턴도 만족하지만 교육청 규칙이 먼저 걸려야 한다):

| 순서 | 패턴 | 분류 |
|---|---|---|
| 1 | `교육청` 포함 | 교육청 |
| 2 | `조달청` 포함 | 조달청 |
| 3 | `국방부\|군부대\|사단\|여단\|해병대\|공군\|해군\|육군\|방위사업청\|국군` 중 하나 포함 | 국방·군부대 |
| 4 | `농어촌공사\|수산\|어항\|어촌` 중 하나 포함 | 농어촌·수산 |
| 5 | `대학교` 포함 | 대학교 |
| 6 | `공사\|공단\|진흥원\|재단법인\|연구소\|본부` 중 하나 포함 | 공사·공단·진흥원 |
| 7 | `특별시\|광역시\|특별자치시\|특별자치도\|도\|시\|군\|구` 행정단위 패턴 포함 | 지자체 |
| 8 | (그 외) | 기타 |

실제 데이터 샘플(`한국농어촌공사 경북지역본부 의성.군위지사`, `경상남도교육청 경상남도창원교육지원청`, `국방부 국군재정관리단`, `서울특별시 금천구`, `조달청 부산지방조달청`, `부산항만공사`, `국립공주대학교` 등)으로 순서를 검증했다 — 예를 들어 `한국농어촌공사`는 "공사"도 포함하지만 4번 규칙이 6번보다 먼저 걸려 농어촌·수산으로 분류된다.

## UI 변경 (`BidsView`)

기존 필터 블록 위에 검색창+지역 드롭다운 줄을 추가하고, 기존 참가여부 필터 줄 아래에 발주처유형 pill 줄을 추가한다:

```
[검색창 (공고명·공고기관)........................] [지역 전체 ▾]
[공고중] [낙찰] [유찰]                              총 N건        ← 기존
[전체] [참가필요] [참가완료] [패스]                                ← 기존
[전체] [교육청] [지자체] [조달청] [농어촌·수산] [국방·군부대] [대학교] [공사·공단·진흥원] [기타]  ← 신규, flex-wrap
```

- **검색창**: `bid.공고명` 또는 `bid.공고기관`에 검색어(trim, 대소문자 무시)가 포함되면 통과. 빈 문자열이면 전체 통과.
- **지역 드롭다운**: 옵션은 하드코딩된 전체 시·도 목록이 아니라, 현재 로드된 `bids` 배열의 `지역` 값 중 존재하는(빈 문자열 제외) 값만 정렬해서 동적으로 생성 (`전체` 옵션이 항상 맨 앞). "창원" 같은 시·군·구 단위는 이 드롭다운 대상이 아니며 검색창으로 커버한다.
- **발주처유형 pill 줄**: 기존 상태/참가여부 필터와 같은 단일 선택 pill 스타일이되, 옵션 수가 9개(전체 포함)라 한 줄에 안 들어갈 수 있으므로 이 줄에만 `flex-wrap`을 추가한다.

모든 필터(상태, 참가여부, 발주처유형, 지역, 검색어)는 AND로 결합된다.

## 상태 관리

기존 `bidStatusFilter`/`participationFilter`와 동일하게, 새 필터 3종(`searchQuery`, `regionFilter`, `agencyTypeFilter`)도 페이지 컴포넌트(`Home`)의 state로 둔다 — `BidsView`는 조건부 렌더링(`tab === 'bids' ? <BidsView .../> : ...`)이라 탭을 벗어나면 언마운트되므로, 로컬 state였다면 탭을 왔다갔다 할 때마다 필터가 초기화된다. 부모 state로 유지해 기존 필터들과 동일한 지속성을 준다.

`AgencyType`/`RegionFilter`/검색어는 데이터를 다시 불러오지 않는 순수 클라이언트 필터링이므로(이미 로드된 `bids` 배열을 걸러내기만 함), Supabase나 Notion 재조회는 발생하지 않는다.

## 범위 밖

- 시·군·구 단위 전용 드롭다운은 만들지 않는다 (검색창으로 대체).
- 발주처유형 분류 결과를 Notion이나 Supabase에 저장하지 않는다 — 매번 클라이언트에서 `공고기관` 텍스트로부터 즉시 계산한다 (파생 데이터, 영속화 불필요).
- 검색어 하이라이팅, 최근 검색어 저장 등은 하지 않는다.

## 테스트 / 검증 방침

이 프로젝트는 자동화 테스트가 없다. 검증은:
1. `npx tsc --noEmit`
2. `npm run build`
3. 로컬 브라우저에서 검색어 입력, 지역 드롭다운 선택, 발주처유형 pill 클릭 후 목록이 올바르게 좁혀지는지 확인. 여러 필터를 동시에 적용해 AND 결합이 맞는지, 탭을 다른 탭으로 옮겼다 다시 입찰정보로 돌아왔을 때 필터 값이 유지되는지 확인.
